§0 整体分层判定

结论：分层骨架合理、方向成立；但「声明」与「事实」有三处偏差，且每层内部都有回潮 / 残留 / 组织债。

  • 依赖方向成立：五包链零反向 import、零环、零绕过包入口（⚠️ 核查修正：AC1 护栏测试仅覆盖 mobile-renderer 边，五包链反向边并无自动化守护——零反向由实测确认，原「护栏锁死五包链」系证据错配）；main → runtime 零 import、零 pi 协议复制；extensions 顶层 17 包依赖无环（含 shared/ 下 extension-logger、quota-providers 共 19 个 @zhushanwen/pi-* 包）。骨架的「谁可以依赖谁」是对的。
  • 偏差 1：链 vs DAG——五包图画的是一条线性链（renderer 只经 ui 消费），实测 renderer 直连 core 96 文件（精确包名口径，含子路径引用 108）、直连 shared 237 文件、1 文件越层直连 dom-core（1 处 import，原「2 处」有误）。形态是 DAG 不是链。直连本身常见，但文档图应画成事实。
  • 偏差 2：真正的链底叶子没入图——extension-protocol（0.8k 行，零依赖）被 core/ui/renderer/runtime/extensions 五方依赖，是依赖 DAG 的最底层，却不在五包图中。
  • 偏差 3：模块名漂移——renderer 目录的包名实为 @xyz-agent/frontend；renderer 内部 6 个速查表条目中 2 个路径已失效（GuiComponentRenderer 已迁 ui 包、extensions/registry.ts 已升格 core/extension-host）。

跨层共性（3 条）

  • 绞杀迁移是主叙事：chat 域已完整下沉 core（chat.ts 906→31 行），subagent/workflow/fileTree/project 四域停在断点——同层内新旧两种 implementation 并存。
