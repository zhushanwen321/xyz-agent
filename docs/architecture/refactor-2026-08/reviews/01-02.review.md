两份文档整体质量高于一般设计文档：五段骨架完整（P0-1 通过）、无 delta 链（P0-2 通过）、**每个候选都补出了 ≥2 方案对比并标注长期/短期性质**（P0-7/8/9 全通过，这是审查报告原文「每候选只给 1 推荐」缺口的实质补齐）、验收普遍用真实场景（dev 冒烟/Playwright 9222/行为等价对比）且删除类（B1/B2/C1/C4）明确写「禁止以单测为唯一验收」（P0-14 基本通过）。

但对抗式审查逼出 **6 个 must-fix**，集中在两类高价值问题：
1. **验收与改动点脱节、客观不可达成**（C2 漏 2 处 lib/ipc、C5 store 范围不全、B7 漏 3 份 git 跟踪文档）——实施完按文档自定的验收跑会直接红，是最该修的。
2. **一处实质设计缺陷 + 一处概念混淆**：B3 把 DOM 强依赖的 mermaid（`mermaid.render()` 本身需要 DOM，代码 :127-130 自承在 jsdom 返回空串）当作「纯函数」全量下沉进「真 headless core」，与 B2 刚庆祝的 core headless 纯度自相矛盾；C3 把 element 级 `ResizeObserver`（TerminalView/useConstantHeightAssert）混进「window resize 订阅」收敛清单，按文档方案替换会破坏 terminal 容器自适应。

事实准确性（P0-11）抽查：B3（logic 12 文件 1347 行、mermaid:42、i18n 3 文件、4 个第三方依赖）、B4（shared 27 ts/exports 两入口/3993 行）、C1（旧壳唯一消费方、New 壳 9 非测试消费方）、C2（BrowserPane:178 八符号）、C3 clipboard 4 处——这些**核心事实全部准确**（审查报告已修正的 guiComponent/useMessageBusSubscription/logic 12 等口径均被采纳）。偏差集中在 scope 边界的计数（见 SUGGESTION #7/8/9）。
