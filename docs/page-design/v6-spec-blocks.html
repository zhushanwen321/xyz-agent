§5

Block · bash

bash 有两个来源，渲染不同，必须区分：① BashOutputBlock——composer 用 ! 前缀直接执行的 bash，独立系统消息，不可折叠，header 显完整命令 + exit 状态标签；② tool-bash——agent 调用的 bash 工具，嵌在 tool 块内（见 §6），可折叠，展开后用 border 容器渲染命令+输出。失败视觉对照：5A（独立系统消息）exit N 显 warn（哑光金）——用户主动执行的直接反馈需明确成败；tool-bash（嵌 tool 块）failed 走 §6 中性灰策略（无 exit 标签、靠 toolName 降色）——agent 工具调用的成败由 agent 后续 turn 解释，视觉退后。两类 v6 统一：去嵌套卡片视觉冗余。

区分 BashOutputBlock（不可折叠）≠ tool-bash（可折叠） 失败对照 5A exit N→warn（用户直接反馈）· tool-bash failed→中性灰（agent 调用） stroke SquareTerminal icon 1.75（统一，原 spec demo 误写 2） copy BashOutputBlock 输出区顶部行内（不可折叠块也补 copy，复制命令+输出）

§10.5

BgNotifyCard · background 完成通知

§10 subagent 的配套完成通知组件。它是独立 Message 类型（message.ts:269 bgNotify 字段，customType:"subagent-bg-notify"），渲染入口不同于 BlockSubagent——BlockSubagent 渲染发起参数（input，v6 collapsed only 不再展开），BgNotifyCard 渲染完成结果（output）。视觉语义：系统级异步通知，卡片带边框，弱于 user/assistant 气泡、强于 SystemNotice。关系链：subagent 块（§10 collapsed）发起 → BgNotifyCard 完成通知 → 主 agent 后续 turn 总结。

新增 BgNotifyCard（spec 原完全缺失，本 section 补全） 两种形态 单条（可展开）· 批量（不可展开，每 record 一行） 卡片色 按最差状态：failed→danger / cancelled→neutral / else→border

§11.5

GUI 组件规格 · extension 推送渲染契约

这些是 extension 通过 details.__gui__ 协议推送的数据结构，renderer（GuiComponentRenderer）负责渲染形态。无 spec 则 extension 开发者无法对齐推送数据结构。[架构变更] workflow 块（§11）v6 collapsed only 不再内联展开 GUI——GUI 渲染迁移到 drawer workflow tab（点击 workflow 块 drawer.open('workflow', { runId }) 打开），或由 extension 自行呈现（BgNotifyCard / workflow extension 推送仍用同一协议）。tool 块（§6）等其他场景的展开内容仍走此协议（GuiComponentRenderer 优先 → AnsiText → 纯文本）。共 7 种组件：progress-bar / list-tree / stats-line / tab-bar / card / columns / ansi-text。递归容器（card/columns）允许嵌套任意子组件。

新增 §11.5（spec 原仅一句带过，本 section 补全 4 种 + progress-bar 细化） 渲染契约 extension 推 __gui__ 数据结构 · renderer 渲染形态 [架构变更] workflow 块不再内联 GUI（→ drawer workflow tab / extension 自呈现）
