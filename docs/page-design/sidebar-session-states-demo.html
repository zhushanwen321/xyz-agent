状态组合说明

  • streaming/pending/compacting/working 共用同一种 badge 样式：accent-soft 底 + 呼吸竖条 + 耗时。仅状态派生逻辑不同，视觉无差异。
  • waiting/retrying 共用 warn-soft 底 + … 文字 + 呼吸。
  • error 用 danger-soft 底 + ! 静态（不呼吸）。
  • done/stopped 无 badge，只显示相对时间（如 "3h 前"）。
  • 未读点 与选中态独立：选中 + 未读同时存在时，圆点仍可见。
  • 已归档（markedDone）标题 opacity-60，不与 done 状态冲突（done 也可以不归档）。
  • dead 整行 opacity-50 但不带 error badge，用户可点击触发 restore。
  • fork 血缘 显示在 sub 行："↑ fork 自 <父名>"，使用 accent/80 色。
  • hover 整行时 meta 区隐藏，露出底部右角的 ghost 操作按钮（归档/重命名/归类/删除）。

当前已知的渲染问题

  • 问题 1：streaming / pending / compacting / working 四态完全相同。用户无法区分「正在生成」和「在压缩」和「后台还有任务」。badge 只有「呼吸竖条 + 耗时」一种样式。
  • 问题 2：waiting / retrying 二态相同。「等待工具审批」和「自动重试」视觉无差别，用户不知道该不该介入。
  • 问题 3：done / stopped 二态相同。「正常完成」和「用户中断」只靠时间文字，无任何视觉标记。归档态 opacity-60 和 dead 态 opacity-50 仅差 10%，弱化感知差。
  • 问题 4：高频瞬态（pending/compacting）通常 <3s，badge 持续时间极短。badge 大概率在用户看到前已切到 streaming/done。
  • 问题 5：已归档和 dead 的 opacity 差异很小（0.6 vs 0.5），不易辨认。
