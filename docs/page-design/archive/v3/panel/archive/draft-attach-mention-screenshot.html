03 Cmd+V vs Ctrl+V 粘贴双通路 核心对比

两条粘贴通路共享「读剪贴板图片 → 存 tmpdir 文件」的前置步骤，差异在呈现与发送协议。Cmd+V 是富 UI + 结构化直传（顶部缩略图 chip + 光标处 image badge + 发送时 base64 进 pi prompt.images，LLM 直接看到图）；Ctrl+V 复刻 pi TUI，光标处插字面路径文本，走 text segment，LLM 需自主调 read 工具读图。点击下方按钮可实际触发对应效果，× 可删除。

Cmd+V 富呈现 结构化 images 直传

剪贴板图片 → 存 tmpdir 文件 → 顶部预览 chip + 光标处 badge → 发送时 base64 进 pi prompt.images

LLM 直接收到图片（base64），无需额外工具调用。
Ctrl+V 路径文本 复刻 pi TUI

剪贴板图片 → 存 tmpdir 文件 → 光标处插字面路径 → 走 text segment

LLM 看到路径，需自主调 read 工具读图（pi TUI 原生行为）。
04 技术实现要点 信息说明

方案 2 定稿涉及的关键实现点：图片存储、双通路链路、pi 协议、Segment 扩展、@ 预留。

  • 图片存储 存到 tmpdir，文件名 {prefix}-{timestamp}-{random}.{ext}。参考 pi 的 pi-clipboard-{uuid}.{ext} 命名约定，prefix 区分来源（如 paste、drop）。
  • Cmd+V 链路 Electron clipboard.readImage() → .toPNG() → 存文件 → Segment 新增 image 类型 → segmentsToPrompt 时提取 base64 进 pi prompt.images。UI 上同时往 ContextChipsBar 加缩略图 chip 与光标处插 image badge。
  • Ctrl+V 链路 存文件 → 光标处插字面路径文本（如 /var/folders/xx/pi-clipboard-a1b2c3d4.png）→ 走现有 text segment。完全复刻 pi TUI 行为，不改发送协议。
  • pi 协议 RPC prompt 原生支持 images?: ImageContent[]（结构为 { type:"image", data:base64, mimeType }），无需改 pi。Cmd+V 通路直接复用此字段。
  • Segment 扩展 新增 { type:'image'; path:string; name:string }。path 用于预览（local-file://）与发送时读文件转 base64，name 用于光标处 badge 显示。
  • @ 预留 不实现触发。chip 渲染骨架保留（.inline-chip.mention-at），等 session / diff / subagent 等引用需求明确后再接触发逻辑。
