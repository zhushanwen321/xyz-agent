A · xyz 现状 —— 为什么看起来「不够现代」

  • 圆角 3px 为主：--radius-sm: 3px 是默认档 → 视觉语言偏「工程面板」。2024 年后的现代产品默认圆角 8–16px。
  • 分隔靠 1px 边框：tab 框、chip 框、bash 块、变更集、顶栏下划线…满屏 hairline。现代做法是用背景层级分隔，边框只留输入区。
  • 大面积 dim 灰字 + 绝对路径：#6b7280 长路径铺满 → 信噪比低，界面「灰蒙蒙」。
  • 彩色图标噪音：探测失败的 bash 渲染成黄色警示三角 ⚠（exit≠0 是 agent 正常操作）；侧栏每行一个 15px 饱和绿勾。
  • 对话流无列宽约束：宽屏一行 2000+px，远超 60–90 字符舒适行长。
  • 字小行密：正文 12–13px 紧凑排布，长时阅读累。

C · Claude —— 亮暖色的「纸张感」配方

  • 暖米底色（#faf9f5）而非纯白 → 像纸不像屏幕，长时阅读不刺眼。这是「舒服」的重要来源，和暗色系是另一条路。
  • serif 标题 + 15px 正文 + 1.75 行高：出版物式排版，信息层级靠字重/字号/留白，不靠边框和底色块。
  • 赤陶 accent（#d97757） 全局只出现在发送键和徽章上 —— 彩色出现频率越低，出现时越有效。
  • 分隔几乎全靠留白：section 之间 24px+ 空白，hairline 都是暖灰 #e8e4d9 而不是冷灰。
  • 代价：亮暖色与「开发者工具」的心理预期不符（大多数 coding 用户默认暗色）；且 xyz 的 token 体系是暗色优先，全量迁移成本高。

E · 推荐：柔和现代 —— 保留 xyz 身份，借竞品的克制

  • 不换底色：冷蓝 #1a1b1f + #4f8ef7 是品牌识别，竞品化的关键不在抄底色。
  • 圆角默认 3px → 8px，composer/弹层 12px，徽章改胶囊。
  • 内部卡片去边框：bash/变更集/chip 从「border+bg」改为「只 bg」——层级间距已拉开（Δ≥5），边框是冗余的双重分隔。边框只留 composer、popover。
  • 对话流 max-width: 720px 居中：一行 CSS，观感提升最大。
  • 路径降噪：绝对路径 → 文件名加亮 + 灰色目录/摘要。全路径放 hover tooltip。
  • 失败中性化：bash exit≠0 改中性图标 + exit 1 小标签；侧栏绿勾 → 7px 低饱和圆点，选中态用 2px 左缘指示条。
  • dim 提亮减量：meta 文字 #6b7280 → #7d8494 附近，减少使用面积。
  • 保留差异化优势：turn meta pills、结构化 trace、变更集卡片 —— 比 Codex 的「过程全塌缩」更适合审计型用户。
