§1

交互问题总览

SystemPromptPage 本质是两个长文本编辑器，但现状把它当「带开关的文本框」处理，缺编辑器应有的认知负载控制与操作反馈。impeccable 对编辑器有专门评估维度（脏状态 / 保存机制 / 反馈 / 上限防护 / 启动起点），据此列出 7 个问题。C1 / C7 是功能/交互缺陷（必修），其余是交互缺失（必修）。

编号 维度 问题 类别 参见
C1 保存机制 Save 按钮 :disabled="!replaceEnabled" 基于 switch 布尔值。关闭 switch 是有效操作（恢复 pi 默认），但按钮被禁用无法保存。用户改完文本若顺手关 switch，编辑成果丢失。 功能 bug §2
C2 脏状态 无 dirty 追踪。编辑后无法知道「有未保存改动」，离开页面无保护，误触导航即丢失。 交互缺失 §3
C3 编辑器 sizing Textarea min-h-[120px] 偏矮，长提示词只露 5 行；无上限防护，超 16000 字符无视觉提示。 交互缺失 §6
C4 计数器 replace 卡计数器 {{ len }}/{{ max }} 单色 neutral-dim，接近上限（90%）与超限（100%）无状态色变化，超限仍能点保存。 交互缺失 §6
C5 保存反馈 保存是 fire-and-forget，点击后无 loading（用户不知在保存），仅成功后弹 toast。 交互缺失 §6
C6 可访问性 Switch 无 aria-label，屏幕阅读器读不出「替换系统提示词开关」。默认参考折叠区也缺语义。 a11y §4 §6
C7 首次启用 用户从未启用过自定义提示词时，打开 Switch 给一个空白编辑器。用户本想在 pi 默认提示词基础上微调，面对空白无从下手，只能手抄或放弃。正确行为：首次启用应自动拉取 pi 当前系统提示词填入编辑器，作为修改起点。 交互缺陷 §5
C1 必修依据: 关闭 switch 不可保存 = 数据丢失 = 功能 bug，优先级最高
C7 必修依据: 首次启用给空白编辑器 = 无修改起点 = 用户被迫手抄默认提示词或放弃，认知负载过高
编辑器评估维度: 认知负载（一张卡一个意图 + 合理起点）· 操作反馈（dirty/loading/toast）· 保存机制（显式 + 守卫）· 上限防护（计数三态 + 禁存）
不变项: 两卡结构（replace + append）· 显式保存按钮（不自动保存）· 只读默认参考折叠区 · 这三项现状合理，保留
列宽: max-w-720（--content-max-w，与 v6-spec-settings §3 设置内容列统一，左对齐不居中）
§2

C1 · Save disabled 基于 dirty 而非 switch

现状 :disabled="!replaceEnabled" 把「开关是否打开」误当成「能否保存」。但关闭开关本身就是一个需要保存的有效操作（把 replace.enabled 写回 false = 恢复 pi 默认）。修复：Save 的 disabled 改为基于 isDirty（当前编辑态 vs 已保存快照的差异），只要编辑过且未保存就启用，无论开关在哪个状态。

C1 bug disabled = !replaceEnabled（关 switch 不能存） 修复 disabled = !isDirty || overLimit || saving 新增 isDirty = 快照 diff（enabled + prompt）

§5

C7 · 首次启用自动填充 pi 当前提示词

用户从未启用过自定义提示词时，打开 Switch 不应给空白编辑器——应自动拉取 pi 当前系统提示词填入，作为修改起点（用户多半想在默认基础上微调，而非从零写）。判定逻辑：用一个 everEnabled 标记记录「历史是否启用过」（持久化在配置里）。Switch on 时：若 !everEnabled（首次）→ 调 fetchSystemPrompt() 填充 + 置 everEnabled=true + dirty=true；若已 everEnabled（复启用）→ 恢复历史自定义 prompt，不覆盖。下方 demo 可交互：点 Switch 看「首次填充」，再用「重置为首次启用」按钮模拟复启用场景。

§7

编辑器交互（sizing / 计数器 / 保存反馈）

长文本编辑器的三个核心交互。sizing：200px min（首屏可见 ~10 行 mono）/ 60vh max（防撑爆 viewport）/ resize-y（用户可拖）。计数器三态（normal < 90% / warn 90-100% / danger > 100%），超限禁用 Save 并给 danger 边框。保存反馈：点 Save → saving态（Button disabled + spinner + badge 变保存中）→ 成功 toast + dirty 清除。

Textarea sizing（xyz-ui Textarea + class 覆写）

现状 · min-h-120
问题: 120px 仅露 5 行 mono，长提示词需大量滚动，编辑时丢失上下文
v6 · min-h-200 / max-h-60vh
改善: 200px 露 ~10 行；60vh 封顶后内部滚动；resize-y 可拖
min-height: 120px → 200px（编辑器首屏可见行数充足）
max-height: 60vh（超长内容封顶，超出 textarea 内部 overflow auto）
resize: vertical（用户可在 200px - 60vh 间拖拽，禁横向防破布局）
font: mono 12px · line-height 1.7（leading-relaxed，长文阅读）

阈值依据: SYSTEM_PROMPT_MAX_LENGTH 16000（constants.ts SSOT）。runtime setSystemPrompt 超限拒存，前端 over-limit 禁存与之对齐
千分位: 数字用 toLocaleString（1 240 / 14 580）易读
append 卡: 无上限，不显 /max 不进三态，仅单字符数（R3）

未保存
saving
保存中
success
已保存

saving: Save disabled + spinner（13px accent）· badge 变「保存中」· 防 double-submit

error: toast error（保留原信息）· dirty 不清除（仍可重试）· Save 回到 enabled

toast 位置: 沿用 useToast（已存在），不在卡片内联
reduced-motion: spinner 无限旋转保留（信息性动画，非装饰），降级为更慢或保留
