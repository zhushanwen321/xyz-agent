§0

变更总览 + C1 关键修复

现状 SystemPromptPage 每卡片 Save 的 :disabled 绑在 switch 的布尔值（!replaceEnabled / !appendEnabled）—— 关闭 switch 是有效操作（恢复 pi 默认），却无法保存。C1 修复：Save 禁用条件改为「无脏数据」（isDirty = 当前编辑态 ≠ 已保存配置）。同时落地 v6 token 与其余审查项。

C1 修复 Save disabled 基于 dirty，非 switch 布尔 M1 两卡交叉提交 → 页面级单 Save M2 + isDirty / 未保存 badge / 离开确认 M3 v6 token：bg-card + 10px + 去 border + hairline rgba(.04) M4 编辑器 min-h 120px → 208px + max-h-60vh M5 辅助文字 dim → neutral-mid m1 + Save saving 态 + Loader2 m2 + Switch aria-labelledby m3 + 计数器接近上限 warn / 超限 danger + 禁用 Save m4 + 恢复 pi 默认

C1 关键修复：Save 禁用条件（前后）

现状 · bug
// disabled 绑 switch 布尔值 <Button :disabled="!replaceEnabled" >保存</Button> // 关闭 switch 后： // replaceEnabled = false → Save 永久禁用 // 用户无法保存「关闭替换」= 有效操作被阻断
后果: 关闭开关后无法保存，必须先开开关才能点 Save，再关开关——逻辑悖论
v6 · 修复
// disabled 绑 dirty（非 switch） <Button :disabled="!isDirty || isOverLimit || saving" >保存</Button> // isDirty = 编辑态 ≠ 已存配置 // 关 switch → 与已存不同 → dirty=true // → Save 可点，可保存「关闭替换」
isDirty 定义: JSON.stringify(buildConfig()) !== JSON.stringify(savedConfig)

isDirty 计算 + savedConfig 快照（M2）

// loadConfig 成功后存快照（初始 savedConfig = 加载值） const savedConfig = ref<SystemPromptConfig | null>(null) const isDirty = computed(() => { if (!savedConfig.value) return false // 未加载完不算 dirty return JSON.stringify(buildConfig()) !== JSON.stringify(savedConfig.value) }) // save 成功后刷新快照 → isDirty 自动归 false → badge 消失、Save 禁用 async function save() { saving.value = true try { const cfg = buildConfig() await config.setSystemPrompt(cfg) savedConfig.value = cfg // 刷新快照 info(t('settings.systemPrompt.savedToast')) } catch (e) { error(...) } finally { saving.value = false } }
C1 根因: :disabled 绑 !replaceEnabled（switch 布尔）而非 dirty
buildConfig: 已统一两卡为单 SystemPromptConfig（现状即如此），故 M1 页面级 Save 天然契合
savedConfig 初始: null → 加载前 isDirty=false（避免初始闪烁 dirty badge）
导航保护触发: isDirty=true 时离开设置页 / 关 overlay → 弹确认（§4）

§6

状态矩阵（enabled/disabled × dirty/clean × saving）

每卡片（以 replace 为例，append 同理但无 over-limit）在所有状态组合下的视觉与 Save 可用性。供实施时逐态比对验证。核心：Save 可用性 仅 由 dirty / over-limit / saving 决定，与 switch 无关（C1）。

switch dirty over-limit saving 编辑器视觉 计数器 badge Save
on false false false default · 可编辑 mid · N/16000 — disabled（clean）
on true false false default · 可编辑 mid · N/16000 未保存 可点（default）
on true ≥80% false default · 可编辑 warn · 接近上限 未保存 可点（未超限）
on true true false danger · border+ring danger · 已超限 未保存 disabled（over-limit）
on true false true default · 可编辑 mid · N/16000 未保存 disabled（saving · Loader2）
off true — false disabled(opacity .5) · 不可编辑 mid · N/16000 未保存 可点（C1：关闭是有效操作）
off false — false disabled(opacity .5) mid · N/16000 — disabled（clean）
C1 验证: 第 6 行（off+dirty）= Save 可点（修复核心）；现状该行 disabled
Save 可用公式: !saving && isDirty && !isOverLimit（与 switch 无关）
over-limit 仅 replace: append 无上限，over-limit 列恒 false（走 hook 不经 argv）
badge 粒度: 每卡独立 dirty 判定；页面级 Save 统一提交
导航保护: 任一卡 dirty → 离开拦截（§4③）
