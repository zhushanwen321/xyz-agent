§0

数据模型 · 存储分层 · 安全红线

Provider 页所有交互依赖的功能语义基础。provider 是「连接配置 + model 集合」的聚合体，本节定义：①存储分层——provider/凭证/偏好/secrets 各落在哪个文件，明文还是加密；②默认 provider 派生语义——无独立「默认 provider」字段，由 defaultModel 反推；③凭证存储安全红线——哪些是明文、哪些绝不提取。后续 §1–§9 的字段交互均以此为基础。

② 默认 provider 派生语义

无独立字段:
无 defaultProvider。默认值由 defaultModel 反推：providerId = defaultModel.split('/')[0]。故 §1 行头无「设默认」按钮。
设默认入口:
仅在 model 行（§2 子区②）——点 model 的「设为默认」写 settings.defaultModel = "providerId/modelId"。
自动 fallback:
当默认 model 的 provider 被禁用/删除，或 model 被移除 → runtime pickFirstModelProvider 回退第一个可用 provider/model（幂等广播覆盖前端）。
禁用清空:
禁用 defaultModel 归属 provider → 前端先清空 defaultModel（runtime 也会修正），避免指向不可用项。

Coding Plan 额度子系统 · 5 fetcher + 双认证 + 三窗口（quota-presets.ts SSOT）

Coding Plan 额度查询是一个完整子系统（不是单一开关）。5 个内置 fetcher，2 种认证方式（api-key / cookie）。fetcher 类型按 baseUrl 域名 + name 正则自动匹配（matchQuotaPreset），也可手动下拉选择。专属 API Key（api-key 类）适配 router/反代场景：provider.apiKey 可能是 router 的 key，Coding Plan 平台需专属 key（存 secrets 目录，留空 = 复用 provider.apiKey）。三窗口额度：[5h 滚动, 本周, 本月]，每窗口 pct（0-100，null=无限/未订阅→整行隐藏）+ resetSec（剩余秒，null=未知→显示 --）。

测试查询:

三窗口语义:
QuotaWins = [5h 滚动, 本周, 本月] · pct=null→无限（整行隐藏）· resetSec=null→无重置信息（显示 --）。

展示入口:
启用后定时拉取，在 Context 容量区（ContextCapacityPopover）展示额度。

§9

用户旅程 · 完整端到端流程

Provider 页两条主旅程（手动添加 / 导入）与一条管理旅程（展开编辑/启用/删除）的端到端交互流程，标注关键决策点与成功/失败分支。供验收时按旅程走查。无 Modal：添加即新建一行并直接展开编辑，编辑即展开行就地改。

旅程 A · 手动添加 Provider

A1
空态/列表 → 添加
点「添加供应商」（Button default）→ 新建空白行并直接展开编辑态（不弹窗）
A2
填凭据（子区①）
名称/类型/Base URL/API Key + authHeader · API Key 显隐+清除 · dirty badge 出现
A3
验证连接？
子区③「测试连接」可选 · ok→「找到 N 模型」/ fail→「检查 Key」（不收起）
A4
加模型（子区②）
手动添加（名称/输入/上下文/思考）或「自动发现」· 名称空→验证错
A5
保存
底部保存栏点保存（saving→disabled）→ 成功 toast「已保存」+ dirty badge 消失 · 行保持展开

旅程 B · 从其他 Agent 导入

B1
选源
page-header「从其他 Agent 导入」→ Popover 4 源 → 选 1 → 关闭 + emit select
B2
预览（spinner）
importState=previewing · 拉脱敏列表 · 含 parseError/顶层警告横幅
B3
处理冲突
默认勾 conflict=none · 冲突项禁用 · key 缺失 warn · 勾选可导入项
B4
确认导入
canConfirm(≥1 选)→「导入选中」· applying spinner · 对话框保持开
B5
成功/部分
toast「导入 N 个」· partialKeyMissing「部分需手动补 Key」· 失败→内联 error 重试

旅程 C · 日常管理（启用/展开编辑/删除）

C1
切换启用
行内 Switch 点击 → 乐观更新(store) + 持久化 · 失败回滚 + inline-error（无需展开）
C2
展开编辑
点名称 → 展开就地编辑（4 子区）· 任意字段改动 → dirty badge + 离开拦截（§3）
C3
模型行管理
常驻行只 3 控件（名+默认标记 / 启用 Switch 乐观 / 展开+移除）· 点高级 chevron 展开抽屉改 输入/上下文/思考/兼容性/设默认 · 即改即 dirty
C4
删除
行尾删除 → ConfirmDialog「删除 X？将移除其下所有模型，不可撤销」（若 X 是默认 provider，追加「默认模型将重置为首个可用」，因 defaultModel 派生自该 provider）→ 成功移除 / 失败保留弹窗+error
旅程覆盖:
添加(A) / 导入(B) / 管理(C) 三主线 · 含决策点(黄)与成功(绿)标记
失败可恢复:
每步失败均有反馈+下一步 · 无静默吞（impeccable harden）
乐观反馈:
Switch/设默认/删除均乐观或经订阅推回 · 用户感知即时
未保存保护:
编辑改动未存时点取消/收起/切行 → 二次确认防误丢（§3）
边缘情况:
禁用/删除 defaultModel 归属 provider → 前端清空 + runtime 幂等覆盖
