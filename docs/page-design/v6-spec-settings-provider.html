导入流程 · 从其他 Agent 导入

Provider 导入的完整用户旅程（W2）。状态机：idle → previewing → applying → done/idle。交互重新设计把流程拆成清晰四步：①多源选择——Popover 下拉列 4 个源 agent（Pi/ZCode/Codex/Claude Code）；②预览——拉取脱敏 provider 列表，展示冲突/Key 缺失/警告；③冲突处理——同名 provider 默认不勾选并禁用（导入必然 skipped），用户可勾选可导入项；④导入——确认后 apply，成功 toast。边缘情况：源配置解析错误（部分仍可导入）→ warn 横幅不阻断；顶层丢弃警告（协议不支持）→ 顶部横幅；preview/apply 失败 → 内联错误允许重试（对话框保持开）。

§5

Switch 乐观更新 · 状态反馈时序

provider 级与 model 级启用 Switch 的交互时序设计。乐观更新（用户感知「即时响应」）：点击立即改 store，开关即时滑动；config.setProvider 异步持久化；成功则广播回流（权威值幂等覆盖）；失败则回滚 store + 报错（开关弹回 + inline-error）。防双击：API 期间 Switch disabled（toggling Set 记录进行中的 id）。状态反馈三态：on（accent 实色）/ pending（accent + thumb 脉冲，表达「应用中」）/ rollback（短暂 danger 外环，表达「弹回」）。model 级同理，区别是持久化需传完整 models 数组（runtime setProvider 整体替换）。

交互时序（provider 级 onToggleEnabled）

① 点击 Switch → actionError 清空 · toggling.add(p.id) · Switch disabled ② 乐观 setProviderEnabled(p.id, enabled) → store 立即变 · UI 开关即时滑动 ③ 持久化 await config.setProvider(p.id, { enabled }) ④ 成功 广播回流（权威值幂等覆盖 store）· 若禁用 defaultModel 归属 provider → 前端清空 defaultModel ⑤ 失败 setProviderEnabled(p.id, old) 回滚 · actionError = 错误信息（inline-error 显示） ⑥ finally toggling.delete(p.id) · Switch 恢复可点

§6

错误态 · 全场景反馈

Provider 页所有失败路径的反馈设计（impeccable harden）。原则：错误可见 + 说原因 + 给下一步（不静默吞、不只报错码）。分三类：①动作错误（toggle/设默认/删除失败）→ 常驻 inline-error 横幅；②表单验证（模型名称空等）→ sticky 保存栏内 actionError；③连接测试失败→ 表单内 testResult danger；④导入失败→ 预览对话框内联 error（保持开允许重试）。

用户旅程 · 完整端到端流程

Provider 页两条主旅程（手动添加 / 导入）与一条管理旅程（编辑/启用）的端到端交互流程，标注关键决策点与成功/失败分支。供验收时按旅程走查。

旅程 A · 手动添加 Provider

A1
空态/列表 → 添加
点「添加供应商」（Button default）→ 开 ProviderEditModal（provider=null）
A2
填凭据（卡1）
名称/类型/Base URL/API Key + authHeader · API Key 显隐+清除
A3
验证连接？
「测试连接」可选 · ok→「找到 N 模型」/ fail→「检查 Key」
A4
加模型（卡5）
手动添加（名称/输入/上下文/思考）或「自动发现」· 名称空→验证错
A5
保存
点保存（saving→disabled）→ 成功 toast「已保存」+ 关弹窗 · 状态订阅推回

旅程 B · 从其他 Agent 导入

B1
选源
page-header「从其他 Agent 导入」→ Popover 4 源 → 选 1 → 关闭 + emit select
B2
预览（spinner）
importState=previewing · 拉脱敏列表 · 含 parseError/顶层警告横幅
B3
处理冲突
默认勾 conflict=none · 冲突项禁用 · key 缺失 warn · 勾选可导入项
B4
确认导入
canConfirm(≥1 选)→「导入选中」· applying spinner · 对话框保持开
B5
成功/部分
toast「导入 N 个」· partialKeyMissing「部分需手动补 Key」· 失败→内联 error 重试

旅程 C · 日常管理（启用/展开/编辑/删除）

C1
切换启用
行内 Switch 点击 → 乐观更新(store) + 持久化 · 失败回滚 + inline-error
C2
展开详情
点名称 → 凭据只读网格 + 模型表 · model Switch/设默认/thinking→编辑
C3
编辑
行尾编辑按钮 → ProviderEditModal(provider=obj) · 改动→未保存二次确认
C4
删除
ConfirmDialog「删除 X？将移除其下所有模型，不可撤销」→ 成功移除 / 失败保留弹窗+error
旅程覆盖:
添加(A) / 导入(B) / 管理(C) 三主线 · 含决策点(黄)与成功(绿)标记
失败可恢复:
每步失败均有反馈+下一步 · 无静默吞（impeccable harden）
乐观反馈:
Switch/设默认/删除均乐观或经订阅推回 · 用户感知即时
未保存保护:
编辑改动未存时点取消/X/Esc → 二次确认防误丢
边缘情况:
禁用/删除 defaultModel 归属 provider → 前端清空 + runtime 幂等覆盖
