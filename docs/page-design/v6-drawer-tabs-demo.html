Drawer 二级 tab 形态对比

SUPERSEDED · 形态 B 已选定：本文档为早期探索稿（对比 A/B/C 三种形态），数值与最终结论以 v6-spec-drawer.html 为准。下方「你倾向哪种」等交互仅作历史参照，决策已落地。
目标：选定 drawer 的「可关闭 tab」交互骨架。注意核实结论：6 个一级 tab 中，只有 detail（文件预览，最强多实例诉求）和 browser（浏览器，中等）天然适合多实例二级 tab；terminal/git/doc/tasks 是单一内容，强行加二级 tab 会变假二级。
三种形态展示同一个场景：detail tab 下打开了 3 个文件，当前在第 2 个，要关闭第 3 个。
设计张力提示：你最初说「每个 tab 下面都支持二级 tab」。但核实发现只有 detail/browser 合适。所以形态 B/C 设计为「按需出现二级 tab」——只有当一级 tab 的内容支持多实例时才显示二级 tab 栏；单一内容 tab（terminal/git/tasks）不显示。形态 A 则是所有 tab 统一为可关闭 tab（包括给 terminal/git 硬凑）。看完三种后告诉我你倾向哪种，以及「假二级」能否接受。

形态 A · 统一 tab 栏（浏览器式）

取消一级 icon tab，所有打开的面板作为顶部可切换、可关闭的 tab（像浏览器/VS Code 编辑器 tab）。用户可同时打开 detail+git+terminal，在 tab 间切换。点 + 新增。
+ 最灵活，真正的多实例 − 6 个一级 tab 的入口在哪？需另设入口（如左缘 icon rail） − terminal/git 这种单一内容也要变成 tab，语义牵强

形态 B · icon 一级 + 内层二级 tab（IDE 式，按需出现）★推荐

保留顶部一级 icon tab（detail/git/terminal/...）。进入支持多实例的 tab（detail/browser）后，内容区上方出现二级 tab 栏，每个二级 tab 可关闭。单一内容 tab（terminal/git/tasks）不显示二级栏。点 + 在当前一级 tab 下新增实例。
+ 一级入口清晰（icon rail 保留） + 二级 tab 按需出现，不强求单一内容 tab 凑数 + 对标 VS Code 侧栏（icon）+ 编辑器（tab）的双层模型 − 两层 tab 栏占垂直空间（icon 栏 38px + 二级栏 32px）

形态 C · icon 一级 + 面包屑（最简，单实例）

保留一级 icon tab。内容区顶部用面包屑显示当前文件路径 + 预览/变更 toggle。不支持多实例——点新文件替换当前内容（即现状的改良版）。这是最克制的方案，不引入二级 tab 复杂度。
+ 最简单，无二级 tab 复杂度 + 垂直空间最省（仅 icon 栏 38px + 面包屑 30px） − 不满足你「多 tab 可关闭」的需求（单实例替换） − 无法同时对照多个文件 diff

我的推荐：形态 B（icon 一级 + 内层二级，按需出现）。理由：(1) 保留一级 icon tab 入口清晰；(2) 二级 tab 仅对 detail/browser 等多实例 tab 出现，不强求 terminal/git 凑数；(3) 对标 VS Code「侧栏 icon + 编辑器 tab」成熟模型。形态 B 可切换一级 tab 看效果：detail 有二级 tab，terminal/git 无（按需出现）。
