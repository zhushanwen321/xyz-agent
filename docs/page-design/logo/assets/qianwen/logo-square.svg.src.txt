  v2: "预留空间太大了, 希望是 LOGO 比较撑满的状态"
  v3: "截错了, 截掉了 LOGO 的上半部分" ← 修正

## 关键 Bug 修复 (v3)

**v2 错误分析**:
- scale 1.32 + translate(62, -271) 时
- 鱼 inner y 起点 144.91 (源图 y=243), 加 outer transform 后 y_final = 1.32*144.91 - 271 = -79.72
- **鱼头超出 viewBox 上边 ~80 像素被裁!**
- 但 PIL 测出 ys.min()=0 (看起来鱼头在 y=0) 是因为 SVG 渲染时 y<0 部分不画
- 我之前误以为"鱼头贴顶未被裁" → 用户反馈"截掉了上半部分"

**v3 正确数学 (反推 potrace transform)**:

```python
# potrace inner transform: SVG_y = -0.1*(path_d_y + 980.869) + 1224
# 鱼原图 y 范围 243-977, 对应 potrace path_d y 范围 9810-2470
# 应用 inner transform: 鱼 y_inner 范围 144.91-878.91
# 鱼 y_inner 高度 734 (= 977-243 ✓)

# 加 outer scale 1.35 + translate(45, -91):
# 鱼 y_final 范围: 1.35*144.91-91=104.63, 1.35*878.91-91=1095.45
# 鱼 y 范围 105-1095, top 105 + bottom 105 对称居中 ✓
# 鱼 x 范围: 1.35*17.87+45=69.12, 1.35*804.87+45=1131.57
# 鱼 x 范围 69-1131, left 69 + right 69 几乎对称
```

## 当前实现 (v1.2)

```svg
<svg viewBox="0 0 1200 1200">
  <g transform="translate(45, -91) scale(1.35)">
    <g transform="translate(0,1224) scale(0.1,-0.1) translate(-21.334,980.869)">
      <!-- 6 条 potrace path 不动 -->
    </g>
  </g>
</svg>
```

**几何测量** (PIL 验证):
- 鱼 bbox: x[71,1131] y[105,1096]
- 鱼尺寸: 1060x991
- 占 viewBox: x 88.3%, y 82.6%
- 留白: 顶部 105px, 底部 103px, 左边 71px, 右边 68px (几乎对称)

## 重要教训 (写入 memory)

**外层 g transform 必须先验证几何边界, 不能只看 PIL bbox 测得 y_min 就以为 OK**:
- PIL 测 y_min=0 不代表鱼头在 y=0 — 也可能是 SVG 渲染裁了 y<0
- 正确做法: 用 potrace transform 公式反推鱼的真实 y 范围, 再设计外层 transform
- 用户反馈"截掉上半部分"是发现这类 bug 的最快方式
