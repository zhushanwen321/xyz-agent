导入 pi 会话 · 三方案对比 demo

在侧边栏「新建任务」下方新增「导入会话」入口：浏览或搜索磁盘上的 pi session（~/.pi/agent/sessions/<目录>/<ISO 时间戳>_<uuid>.jsonl， 列表优先展示 session 名称，其次短 ID；选中后选择目标 project 导入，导入的会话出现在侧边栏该 project 分组下且可继续对话。 搜索同时接受名称、完整/短 Session ID（uuid 前 6 位，即 pi TUI 里 72cd03 式短标识，前缀匹配真实文件名 <时间戳>_<uuid>.jsonl）与 .jsonl 绝对路径。 已存在于太极的 session 显示「已导入」不可重复导入。三个方案共享同一套扫描与导入 RPC，仅界面形态不同。

方案 C

侧栏子视图 + 主面板预览 · 非模态

点击后侧边栏切换为导入子视图（返回按钮退出），主面板变成所选 session 的全量预览：标题、完整 ID、来源文件、首条消息摘要。适合「翻历史、先看再导」的批量场景；非模态，随时可切走。信息量最大，实现范围也最大。

交互点「导入会话」进入子视图；选条目 → 主面板出预览 试一试点不同条目看预览联动；「返回会话列表」退出 同构sidebar activeTab 子视图架构内的临时视图

§5

三个方案怎么选

三者共享同一套扫描/去重/导入 RPC 与数据模型（project 归属在导入时确定，默认当前激活 project 可改），差异只在界面形态。
