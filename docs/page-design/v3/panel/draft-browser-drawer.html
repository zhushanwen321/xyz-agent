Drawer 集成 Browser · 方案对比

在 SideDrawer 的 browser tab 内嵌入真实网页浏览器，让 agent 输出的链接在应用内打开。本稿并排对比三种嵌入式技术路径的真实渲染差异，并提供推荐方案（WebContentsView）的交互原型。

§1

三种方案，加载同一个 URL 的差异

同样在 drawer 内尝试加载 https://github.com 这种典型站点。iframe 受目标站 X-Frame-Options / CSP frame-ancestors 限制，多数现代站点会拒绝嵌入；webview tag 和 WebContentsView 都是独立 webContents，不受此限。

<webview> tag

Electron discouraged（42 仍可用）
方案 C · 推荐

WebContentsView

主进程 native view，Electron 30+ 推荐
任意 URL 正常加载
可独立 preload，主进程完全可控
需手动 setBounds 同步 drawer rect
iframe 不是"取舍"，是硬伤。它无法加载 agent 最可能给出的链接类型（搜索结果、文档站、GitHub、任何登录页）。X-Frame-Options: DENY 和 frame-ancestors 'none' 是目标站设置、本应用无法绕过。实用率会极低。

§4

触发流程：从点击链接到 drawer 打开

MVP 触发源是"用户点击 agent 输出的链接"。整条链路只有一处拦截点改动，不需要动任何消息渲染组件。

STEP 1

用户点击链接

agent 消息里的 <a href>，所有消息渲染点统一委托。

STEP 2

MarkdownRenderer 拦截

useMarkdownInteractions.ts 的 onClick 委托捕获，preventDefault。

STEP 3

drawer.open

调 drawer.open('browser', { url })，替代原 openExternal。

STEP 4

BrowserPane 挂载

SideDrawer 切到 browser tab，渲染 <BrowserPane :url>。

STEP 5

IPC → 主进程

browser:navigate IPC，主进程 BrowserViewManager 加载 URL。

STEP 6

WebContentsView 加载

view attach 到窗口，rect 由 renderer 推送，导航事件回传前端。

需保留 openExternal 作降级：非 http(s) 协议、view 加载失败、或用户显式选"在系统浏览器打开"时，回退原链路。openExternal 完整保留，不删除。
