本 demo 是 composer「文件 / 图片传递」功能的视觉 SSOT，替代已归档的 v1（方案 2 定稿原型）。v1 的多个核心决策已被代码推翻：Ctrl+V 路径文本通路已删除（粘贴统一为富呈现，避免截图静默丢弃）；图片不再存 tmpdir，改为 <dataDir>/attachments/<sessionId>/ 持久化 + landing tmpdir 迁移；badge 显示 displayName（用户可读）而非 fileName（uuid 磁盘全名）。下方 6 区块覆盖三前缀语义、附件三入口、landing 迁移时序、编辑带图、displayName vs fileName、历史图片渲染。

03 landing 态粘贴 + tmpdir 迁移时序 新增（v1 盲区）

landing 态（session 延迟创建，尚未拿到 sessionId）粘贴图片是 v1 demo 的盲区。writeSessionImage 在 sessionId 为空时降级落 OS tmpdir，发送时 submitFirstMessage 创建 session 后需把 tmpdir 图片迁移到 attachments/<sid>/ 持久化目录，否则 macOS 3 天清理 tmpdir 后重开 session 历史图丢失。

landing 态（session 未创建）
  1. 用户粘贴图片
  2. writeSessionImage(sessionId='') → 落 OS tmpdir path = /var/folders/xxx/uuid-image.png
  3. 用户输入文字 + 点发送
  4. Composer.onSend 快照 segments（含 image segment）
  5. submitFirstMessage(segments)
  6. sessionApi.create() → session 创建，拿到 sessionId
  7. 扫描 segments，找 path 在 tmpdir 的 image isTmpdirPath = path 不含 /attachments/ 段
  8. migrateSessionImage(fromPath, sessionId, fileName) tmpdir/uuid-image.png → attachments/<sid>/uuid-image.png
  9. 更新 segments.path 为 attachments 路径
  10. chat.send(sid, finalSegments) appendUser + extractImages 都用迁移后的 path
降级：tmpdir 文件已被 OS 清理
migrate reject → Promise.allSettled 跳过 → toast 提示 → 文本占位 [图片 N] 仍发

为什么需要迁移：macOS 对 tmpdir（/var/folders/...）的清理策略是「3 天未访问自动删除」。若 landing 粘图后图片留在 tmpdir，用户重开 session（几天后）时历史消息的图片 path 已失效，local-file:// 加载 404 → 降级 badge 兜底（见 §06）。迁移到 attachments/<sid>/ 后，图片随 session 持久化，重开仍可加载。单文件迁移失败不阻断发送（Promise.allSettled 跳过 + toast 提示），文本占位 [图片 N] 仍正常发出。

05 displayName vs fileName 新增

image segment 有三个字段，语义分离。badge 显示 displayName（用户可读），不显示 fileName（uuid 前缀，对用户冗余且不美观）。v1 demo 的 badge 显示 screenshot-时间戳.png（可读），但代码实际一度显示 uuid-image.png（不可读），本次方案拆分 displayName vs fileName 后 badge 确实显示 displayName。

badge 显示对比
dbfdb3c8-bc70-4eb4-8308-e259a0d5f0b4-image.png × ❌ 旧：fileName 混用（uuid 前缀，不可读）
截图-20260725-1530.png × ✅ 新：displayName 显示（可读）
  • fileName 磁盘全名（含 uuid 前缀，用于磁盘定位 / 日志）。格式 {uuid}-{sanitized}.{ext}，如 dbfdb3c8-...-image.png。uuid 前缀保证唯一性，sanitized 为剥离路径分隔符后的用户名。
  • displayName 用户可读名（badge label / 缩略图 alt 显示）。不含 uuid 前缀。生成规则见下方。
  • path 绝对路径（磁盘 IO 用）。<dataDir>/attachments/<sid>/<fileName> 或 landing 态 tmpdir 路径。extractImages 读此 path 转 base64，local-file:// 加载也用此 path。

displayName 生成规则（writeSessionImage 主进程侧）：

  • 粘贴截图 剪贴板无原文件名（blob.name 为空）→ sanitized 退化为 'image' 占位 → displayName 用 截图-YYYYMMDD-HHMM.ext（本地时区时间戳）。
  • 拖拽 / +菜单 有原文件名（blob.name 非空）→ sanitized basename（剥离 / \ : 与控制字符防目录穿越，去重扩展名）→ displayName 用 {sanitized}.{ext}。
06 历史消息图片缩略图 + 降级 badge 新增

历史消息中的 image segment 由 <ImageThumb> 组件渲染。local-file:// 协议白名单含整个 <dataDir>/attachments/ 前缀，重开 session 历史图仍可加载。path 失效时（tmpdir 被清理 / 文件损坏 / 白名单 403）img onerror 触发降级 badge 兜底。v1 demo 无历史渲染，本区块补全。
