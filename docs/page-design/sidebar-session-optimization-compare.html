侧边栏 Session 状态 — 优化方案对比

三个方案解决同一个问题：9 种 DerivedStatus 在侧边栏的视觉区分度不足。每个方案独立展示完整侧边栏 mock + 变更 diff 表。当前方案（现状）见 sidebar-session-states-demo.html。

方案 A · 图标语义化

每个状态用独立图标 + 专属颜色，一眼区分。把 STATUS_ICON（已有但未在 SessionItem 渲染）引入 badge 区。

方案 A 推荐
每态独立图标 + 颜色，信息密度高，一眼可辨。

  • △ compacting/pending 通常 <3s，图标切换闪烁可能比竖条更明显

维持当前 badge 结构（竖条 + 胶囊），靠颜色细分状态组。不引入新图标，改动集中在 class 映射。

方案 B
竖条/胶囊结构不变，颜色区分状态组。

  • ✓ 改动面小：只改 class 映射 + 模板微调，不引入新组件
  • ✓ 颜色语义清晰：accent=活跃运行 / info=系统操作 / purple=等待确认 / green=后台
  • ✓ done/stopped 终态区分成本最低（小圆点 vs 删除线）
  • △ 依赖色彩辨识度（色弱用户可能 compaction 和 pending 不易分）
  • △ retrying 的 ×2 是临时启发式信号，不如图标正式

方案 C · 最小改动

只改最容易感知的歧义点：running badge 加文字标签区分子状态，done/stopped 加小符号。其余保持原样。

方案 C
改动最少，只解决最明显的 3 个歧义。

  • △ 短暂态（pending 3s）的中文标签可能闪烁未读完就消失了
  • △ 本质是 workaround，不如 A/B 方案的结构性区分
