## Summary

4 must-fix, 6 suggestions, 2 info.

总体判断：前两轮覆盖的「设计→计划映射 / 内部自洽 / 验证设施存在性」骨架依然成立，本轮不推翻。**但 v3/v4 增量（决策 4 秒级信号 + 决策 5 四级投影 + v4 枚举重定义）存在一条系统性偏差：两份文档的「sidecar 中心」叙事与扩展实际生命周期不符**。源码核实表明扩展的终态收尾有两条路径——`doFinalizeRecord`（写 `.finalized`/`.cancelled` sidecar）与 `doFinalizeRoundToIdle`（**不写任何 sidecar、且删除 `.alive` marker**），而后者被最高频的两类状态转换共用：one-shot 成功完成与 chatMode 轮次完成。由此产生 4 个 must-fix：A9「已核」断言对 one-shot 成功路径失实（MF-1）；投影矩阵对 chatMode 等续聊（进程已回收的 Path B）落第四级误报 done、与自身 waiting/hasBackgroundWork 语义矛盾（MF-2）；closedReason 值域（实测 6 值）→ 新 6 态映射表在两文档均未落，stopped 态全矩阵无数据源（MF-3）；A10 候选 b 的终止帧在 chatMode 首轮/冷路径轮次完成时也会发出（`stream.dispose()` 在 finally），探针只验到达性不验特异性（MF-4）。维度 3 三项实验设计核查：A5 的 tail -F 形态有单向失真（SG-4）；E2E 并发假设成立（INFO-1）；场景 7 孤儿退出机制存在但缺超时兜底（SG-5）。

## 各维度结论

### 维度 1：设计 v3/v4 增量改动的对抗审查

- **决策 4（秒级信号候选 a/b）**：候选 b 有未论证的误触发面（chatMode 首轮/冷路径轮次完成也发终止帧，MF-4）；候选 a 的 token 验证已覆盖（INFO-2），但发起点集合不含轮次完成导致 waiting 数据源断链（SG-1）；候选 b 帧序与 §5.1 时间线叙事相反（并入 MF-4）。
- **决策 5（投影矩阵）**：内在矛盾确认——矩阵的 sidecar 中心叙事与 `doFinalizeRoundToIdle` 共用路径（one-shot 成功 + chatMode 轮次完成，均不写 sidecar 且删 `.alive`）系统性不符：one-shot 成功靠第五级兜底侥幸收敛但 A9/时间线失实（MF-1）；chatMode Path B 与孤儿同形误报 done、与 waiting/hasBackgroundWork 语义自相矛盾（MF-2）；「bg-notify running entry（轮次通知）信谁」的规则缺失（并入 MF-2——chatMode close 的 60s 窗口期该组合靠第三级 `.finalized` 接住结果正确，但实现若延续 extractor「最后 entry 覆盖」现状模式则会错）。closedReason 值域（实测 6 值）→ 新 6 态映射表不存在，stopped 无数据源（MF-3）。
- **SubagentStatus 旧→新映射完备性**：旧 6 值中 done→done、failed/crashed→error、cancelled→cancelled 可推断；running→streaming/waiting 依赖 idle 位（SG-1 断链）；closed→done/stopped/error 依赖 closedReason×error 组合（MF-3 缺表）。历史 session JSONL 的 legacy 值（done/failed/cancelled/completed/error/canceled/crashed/active/pending）经 normalizeSubagentStatus 现状兼容层可归一，方向无缺口，但归一目标表未写（并入 MF-3）。

### 维度 2：计划与设计 v4 的一致性漂移

- 设计 §5.1 时间线 terminal 信号 vs 计划 P3 kind 枚举：一致（started/notify/terminal 两文档对齐），无漂移。
- 决策 5「hasBackgroundWork 连带语义」在计划 P4 有落实行，但文件指向错误（SG-3：真正落点在 subagent.ts store 的 hasRunning 实现）。
- 设计 §11 探针表与计划 P0 清单：A9 已核不在 P0 ✓ 一致；A10 在 P0 清单但设计把它放在 §4.1 而非 §11，回写位置漂移（SG-6）。
- v4 枚举重定义的设计内残留（§5.2/§7.2/§8 场景 7 旧值）计划已用新值——设计侧待清理（SG-2）。

### 维度 3：实验设计有效性

- **P0-A5**：tail -F 双异步流观测有单向假阴性失真，应改事件驱动直接 readFileSync（SG-4）。runtime 侧挂钩子实测亦可（event-adapter 收到 tool_execution_end 中间事件时读盘），但形态 B + 直接读文件已足够。
- **E2E 并发假设**：成立（INFO-1，executionMode sequential + background 立即返回 + pool 并发）。
- **P4 场景 7 孤儿退出**：机制已核实存在（rpc stdin EOF → shutdown → exit），风险仅剩 dispose 卡住的长挂，补轮询超时即可（SG-5）。
