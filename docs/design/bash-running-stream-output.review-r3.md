## Findings

| 优先级 | 位置 | 维度 | 描述 | 修复方向 |
|--------|------|------|------|----------|
| SUGGESTION | §6.4 D4 硬切回退分支（L236）+ §8.2 S5 命令 ② | P0-12 对抗（降级 P1，见判定理由） | **硬切分支尾窗起点可能落在未闭合 ANSI 转义序列中段**。尾窗起点 = 原文中段任意截断点，若该点恰在 `\x1b[...m` 序列内部，尾窗以残片（如 `[31m`）开头：AnsiText（ansi_up）对不完整序列会按字面渲染残片，running 期尾窗首部出现临时乱码；且此前残片未闭合可能使后续正文继承错误颜色直到下一个完整转义。**降级理由**（对抗后未被说服为 must-fix）：① 影响面仅 running 期 transient 态展开区首部（换行锚分支不受影响——换行天然是序列边界外的安全起点，而典型 ANSI 输出按行着色，硬切分支 = 无换行的 base64/minified 场景，本身几乎不含 ANSI，两分支的坏场景交集为空集附近的极小概率）；② end 全量快照恢复；③ 修复方向轻量（见右），不构成架构影响 | 二选一：a) U1 硬切分支截断后若首字符序列非 `\x1b` 开头的合法转义，向前吞掉至下一个 `\x1b`（一行代码级）；b) 在 D4 已接受代价清单中按四要素补一条登记（量级：硬切分支 + 含 ANSI 的组合概率极低；恢复路径：end 全量快照） |
| SUGGESTION | §6.4 D4 硬切回退分支（L236） | P1-8 / P0-20 关联 | **码点边界只防代理对，不防 grapheme cluster**。ZWJ emoji（👨‍👩‍👧 = 多码点）或组合字符（e + U+0301）被劈在码点边界上时，字形拆开渲染为 tofu / 分离部件。量级同上更小（running 期 transient + bash 输出含 ZWJ/组合字符的概率低 + 帧间隔 100ms 后下一帧大概率自愈到新截断点），属登记级 | D4 硬切分支补一句声明：「码点边界不保证 grapheme 完整，劈开 ZWJ/组合字符字形时渲染为分离部件，属已接受代价（量级：仅 running 期、自愈于后续帧或 end 快照）」——不必实现 Intl.Segmenter |
| SUGGESTION | §6.4 D4 代价清单（L242） | P0-20 四要素 | **已接受 UX 代价（尾窗静默截断）缺「重审触发条件」**。同一 bullet 的内存代价有显式重审条件（L241：>5 并发长输出 session / 重连卡顿报告），UX 代价子项只写了量级/恢复路径/裁决理由，无「到什么程度不再可接受」。属登记完备性缺口，不影响方案成立 | 补一句重审触发条件（如：用户报告误以为输出丢失 / 要求 running 期查看上文成为常态诉求 → 重审加截断标记） |

### 指定攻击点 ③：四处联动一致性核对（通过）

- **§4 后图 / ring 段（L151、L168）**：「帧经 U1 瘦身后有界，见 D4」+「换行锚优先、无换行硬切回退码点边界」——与 D4 规格逐词一致。
- **§7 U1（L293）**：两分支 + 码点边界 + 条件化不变式 + 「单测必须覆盖无换行硬切分支（含代理对边界用例）」——规格级与测试要求齐备。
- **§8.2 S5（L345）**：双命令与分支标注正确——① `yes … \| head -c 2000000`（换行锚分支，含修订方纠正的 yes 事实）② `tr '\0' 'a'` 构造 2MB 无换行单行（硬切分支），通过标准含「命令 ② 尾窗无半字符/乱码——码点边界回退生效」（可证伪，正是 Findings #1 场景的手测观察点——若采纳 #1 方案 a，该观察点顺带覆盖）。
- **§9.2 U1 行（L366）**：测试描述为「三形态 + 截断不变式」，未点名两分支与代理对用例——但 §8 单测职责（L347）已显式点名「截断两分支（换行锚 / 无换行硬切含代理对边界）」，§9.2 是拆分粒度描述、§8 是测试职责 SSOT，两处不矛盾。**INFO，不构成 finding**。

### 事实独立核实

- **yes 输出换行**：`yes <str>` 每次输出 `<str>\n`（POSIX 定义），修订方对 r2 报告「yes 不输出换行」的纠正正确；S5 命令 ① 确实落在换行锚分支，命令构造成立。
- **硬切分支码点回退方向**：「高代理 0xD800-0xDBFF 前移一位」——截断点落在高代理码元（代理对前半）时向前退一个码元，使代理对整体落在保留侧/丢弃侧之一，方向正确。
