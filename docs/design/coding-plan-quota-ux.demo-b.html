方案 B · 单按钮「保存并测试」 · 推荐

把「保存」和「测试」合成一个动作。用户填完参数只做一件事：点「保存并测试」。缺什么在字段旁边直接说（不是挤在按钮后面）。

凭证来源用分段控件显式表达 —— 「用上方凭据」和「用专属 Key」二选一，消除「空输入框到底是没填、还是继承」的歧义。

优点：一个动作、心智最简单；缺什么一眼看到；凭证来源不含糊
代价：分段控件是设置页里的新元件；与底部 provider 保存条仍是两套提交模型
改动量：中（composable 重构 + 区块重写）
