## 新攻击点推演

### ① 多 session 并发 ring 聚合量级 — 不构成 must-fix

r2 已核 message-bus ring 是 per-session（L18「per-session 消息 store」、§6.4 量级已按「≤16MB/活跃流式 session」计）。聚合上限 = N × 16MB，文档在重审条件中已放「>5 个并发长输出 bash session 常态化」触发器（L241），即隐含接受 ≈80MB 聚合常态窗口。数字本身未显式写出 → 列 suggestion（见 S-1）。不击穿：80MB 是桌面进程可承受量级，且重审通道存在。

### ② 硬切尾窗起点落在未闭合 ANSI 转义序列中间 — 击穿，规格缺口（must-fix）

反例：原文 `…\x1b[3` + 尾窗起点落在 `[3` 之后（硬切分支无换行锚保护）→ 尾窗以孤立的 `[38;5;196m` 中段或残缺 CSI 开头。两个后果面：

1. **outputRaw → AnsiText 渲染**：残缺序列开头（如尾窗以 `8;5;196m` 起始）不是合法 CSI，ansi_up 按字面文本渲染——用户在展开区看到一段裸露的转义参数碎片（非乱码字符，但属可见渲染异常）。此外尾窗起点前的颜色状态丢失，后续文本颜色继承不确定（纯视觉、transient，可接受）。
2. **output = stripAnsi(截断后原文)**：stripAnsi 对残缺尾序列同样可能残留残段文本。

频率不低：ANSI 彩色长输出（pnpm/测试工具）+ 超长行场景即触发；而 r2 修订刚把硬切分支规格化（含码点边界）却没有覆盖转义序列边界——这是新规格自身的缺口，不是登记过的已接受代价（D4 已接受 UX 代价只有「尾窗无截断视觉标记」一项，L242）。

**定级**：P0-12（改 A 影响 B——U1 截断规格影响 U3 AnsiText 渲染面，遗漏连带规格）。修复方向二选一（修订方裁决）：a) 硬切分支起点回退时一并吞掉残缺转义序列——起点若落在 `\x1b` 与序列终结符之间，向后跳到首个 CSI/SGR 起点之后（换行锚分支天然从行首起、通常不受影响，可一并声明）；b) 按代价四要素显式登记接受（量级：仅 running 期展开态、残缺序列一闪而过 @100ms 节流被下一帧覆盖；恢复路径：end 全量快照）。任一落位即可，当前文档两样都没有。

### ③ detail 通道 truncation/fullOutputPath 元数据与尾窗并存 — 一致性可接受，列 suggestion

并存事实：payload 同时携带 pi 侧 `details.truncation`（pi 自己 50KB/2000 行截断的元数据）与本方 8KB 尾窗 output。不一致窗口存在：pi 快照未触自身截断（`truncation` 为空/false）但快照 > 8KB 时，本方尾窗静默切——元数据说「没截断」而展示的是尾窗。核验：running 态 detail 在展开区不渲染（detail 消费面是 GUI 提取与 end 后 meta），用户可见面不暴露该矛盾；fullOutputPath 指向完整文件，恢复通道存在。不构成 must-fix，但语义分层（「pi 截断元数据」vs「传输层尾窗」两层截断语义不同）值得一句话登记 → S-2。
