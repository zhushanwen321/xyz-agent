## 修订方三问回答

**(a) 最坏组合阻塞上限——量级边缘确认，护栏建议见 Findings 1**。无需单轮候选数硬上限：mtime 降序排序使首候选即本 record 文件（agent_end 时刻最新修改），命中即停使实际读取 = 1 次命中读，候选数上限的护栏价值被排序覆盖；异步流式读逃生门已为占比显著形态预留。

**(b) 接入点 2 收尾延迟占比——现有声明已覆盖，无需单独立上限**。「close 收尾接入点 2 为一次性单轮（无窗口重试），同量级」已如实声明；且该形态（提前 kill + 握手全失败）无 keep-alive 等待在先，finalize 延迟 = 单轮扫描量级（排序护栏生效后 ≈ 1 次命中读），相对 SIGTERM→30s 升级链与 spawn 冷启动本身不构成占比问题。

**(c) 「命中即停」实现约束——无需写死**。字面语义「整文件读 + 行扫描提前返回」与「增量流式读 + 命中即停」两种实现都满足已声明的两态量级（miss 态两者等价；hit 态增量读更省但 readFileSync 整读也仅一次定界成本，且 session-pending 首读全量的 readFileSync 是同仓先例）；重形态已由 ⛔ 探针 + 异步流式逃生门承接。实施按探针量级结论自选 IO 形态即可，不构成契约缺口。
