# .agents 目录迁移 + 发布线修复（深度整合）

## 背景认知

经完整调研，源仓 `.agents/` 资产分为 5 类：

| 类别 | 处置 | 依据 |
|------|------|------|
| 源独有 review agent（2个） | **迁移** | 补全 extension 维度 |
| 源独有 pr-cr-fix skill | **深度改造迁移** | 激活当前 8 个孤立的 review agent（当前没有任何 skill 调度它们） |
| 源独有 dev-link skill | **不迁移** | 依赖 `~/.pi/agent/extensions/` 路径；extensions/ 已在仓库内，开发直接改源码，无需 link |
| 重名 skill/agent（merge/code-review/pull-request + 4 agent） | **保留当前版本** | 当前版针对 Electron/Vue 深度特化；源版针对纯 extension。当前是目标项目 |
| 源顶层 `skills/`（12个实体副本） | **不迁移** | 全局 `~/.agents/skills/` 已有；项目级不应重复持有 |

同时 CI 审查（background reviewer）发现发布配置 2 critical + 3 major，用户要求**全部修复**。

关键修正：reviewer 的 C1（CI 缺 changeset version）**不是 CI bug**——源仓模式是「本地 changeset version + CI 只 publish」（merge skill 阶段 4）。**真正的 gap 是当前 merge skill 没有 npm 发布线**。

## Phase 1：CI/发布配置修复（C1-C2 + M1-M3）

### 1.1 修复 C2：typebox peerDep 写错（4 个包）
将 `extensions/{context-engineering,evolve-daily,model-switch,unified-hooks}/package.json` 的 `peerDependencies.typebox` → `@sinclair/typebox`。model-switch 同时有 `@sinclair/typebox` 和 `typebox`，去重只留前者。

### 1.2 修复 C1：merge skill 增加 npm 发布线
当前 merge skill 阶段 4 只做 Electron bump（`npm version` + `v*` tag）。增加 **npm 发布子阶段 4N**：
- 4N.1 检查 `.changeset/*.md`（本次 PR 的 changeset）
- 4N.2 `pnpm changeset version`（本地消费 changeset，bump extension 版本）
- 4N.3 commit 版本变更 + 打 `npm-v<version>` tag + push
- 4N.4 CI（release-npm.yml）自动 `changeset publish`

**位置**：merge SKILL.md 阶段 4 之后插入「阶段 4N: npm extension 发布（可选）」。标注为「仅当本次 PR 含 extension 改动且有 changeset 时执行」。release-npm.yml 本身**不改**（CI 只 publish 是正确设计）。

### 1.3 修复 M1：release-npm-dev.yml 预发布 dist-tag 加固
当前 dev 预发布依赖本地脚本提交 `.changeset/pre.json`。给 CI 加防护：publish 步骤前检测 `.changeset/pre.json` 是否存在，不存在则跳过 publish 并警告（避免误发 latest）。

### 1.4 修复 M2：npm-prerelease.sh 支持指定包
当前 npm-prerelease.sh 只 bump `@xyz-agent/extension-protocol`。改为：接受包名参数（`bash scripts/npm-prerelease.sh @zhushanwen/pi-goal`），无参数时默认 extension-protocol。changeset 模板用传入的包名。

### 1.5 修复 M3：changeset 加 linked 组
`.changeset/config.json` 的 `linked` 加入有内部依赖关系的包组，避免版本漂移：
```json
"linked": [
  ["@zhushanwen/pi-quota-providers", "@zhushanwen/pi-model-switch", "@zhushanwen/pi-statusline"]
]
```
（这三个有 workspace:* 依赖链）

### 1.6 minor m1：vision 加 test 脚本
`extensions/vision/package.json` 加 `"test": "vitest run"`（即使空测试套件，保持 CI 一致性）。

## 风险

1. **pr-cr-fix 7 维分批**：subagent 并行上限 5，7 个 review 维度需 5+2 分批。源仓是 5 维全并行。分批时序需在 SKILL.md 明确
2. **pr-pre-merge.sh 命令适配**：源仓用 `pnpm -r typecheck`，当前项目 typecheck 分散在多处（extensions 有独立 tsconfig）。需实测
3. **changeset linked 组**：linked 模式会强制组内版本同步。需确认 model-switch/statusline/quota-providers 确实需要同步发布（它们有 workspace:* 依赖）
